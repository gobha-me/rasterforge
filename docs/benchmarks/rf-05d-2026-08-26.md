# RF-05d scalar benchmark baseline — 2026-08-26

This is the first reproducible RasterForge workload baseline. It measures the
scalar implementation and records evidence; it is not a correctness test, a CI
threshold, or a cross-machine performance promise.

## Provenance and machine

- Source: `a90fa57c219ee68a045b10f68cafdf526f963504`
- RasterForge: `0.4.3`, tweak 1, clean worktree
- Compiler: GCC 14.2.0, Release
- CMake: 3.28.3
- zlib: 1.3
- OS: Linux 6.12.74 x86-64
- CPU: 13th Gen Intel Core i9-13900H, 14 cores / 20 hardware threads
- Sampling: 20 samples, at least 25 ms per batched sample

The workload source, caveats, build command, and column definitions are in the
[benchmark guide](../../benchmark/README.md). The 768x1024 workload is a
Venice-derived upper proxy; it is not an established AIForge display policy.

## Interpretation

- At 320x180, bridge copying is 18.6 us and one output allocation. Keeping the
  copy visible remains architecturally correct, but it is not the dominant
  scalar cost in this workload.
- Triangle filtering is the dominant pixel kernel: 1.60 ms for same-extent
  320x180 and 7.43 ms for a 768x1024-to-320x180 cover fit. Its four coefficient
  vectors explain the five observed C++ allocations and make its temporary
  resource contract visible.
- PNG decode is 1.14 ms at 320x180 and 17.45 ms for the upper proxy. The C++
  counter sees only the final image allocation; the separate temporary floor
  records RasterForge's bounded codec contract without pretending to measure
  codec C allocations or RSS.
- Solid and image compositing remain below 0.43 ms at 320x180. Nearest fit is
  below 0.17 ms. These scalar results establish no consumer bottleneck that
  justifies an optimization issue, so none is opened from this baseline.

For the concrete TermForge 30 FPS frame budget of 33.33 ms, the same-extent
320x180 triangle fit, solid composite, and bridge copy total about 1.96 ms at
their medians. This comparison excludes TermForge rendering, encoding,
transport, terminal work, and scheduling, all of which remain outside
RasterForge's benchmark boundary.
